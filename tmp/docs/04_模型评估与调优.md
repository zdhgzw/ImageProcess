## 一、模型评估指标

### 1.1 语义分割核心指标

**mIoU（Mean Intersection over Union）**：
```
IoU = 交集面积 / 并集面积 = TP / (TP + FP + FN)

mIoU = (IoU_class0 + IoU_class1 + ... + IoU_classN) / (N+1)
```

**其他指标**：
- **Pixel Accuracy（PA）**：像素准确率
- **Precision（精确率）**：预测为正的样本中真正为正的比例
- **Recall（召回率）**：真正为正的样本中被正确预测的比例
- **F-Score**：Precision和Recall的调和平均

### 1.2 指标对比

| 指标 | 优点 | 缺点 | 适用场景 |
|-----|------|------|---------|
| mIoU | 综合评估分割质量 | 计算复杂 | 最常用，论文标准 |
| PA | 计算简单 | 忽略类别不平衡 | 快速评估 |
| F-Score | 平衡Precision/Recall | 不考虑空间关系 | 二分类任务 |

## 三、mIoU指标解读

### 3.1 mIoU数值参考

| mIoU范围 | 评价 | 说明 |
|---------|------|------|
| > 0.90 | 优秀 | 高质量分割，接近商用水平 |
| 0.75-0.90 | 良好 | 可用于实际应用 |
| 0.60-0.75 | 中等 | 需要进一步优化 |
| 0.45-0.60 | 较差 | 模型欠拟合或数据质量问题 |
| < 0.45 | 很差 | 基本不可用，需重新训练 |

### 3.2 单类别IoU分析

**案例：二分类（猫狗分割）**

```
mIoU: 0.7234

| classes     | IoU   | Recall |
|-------------|-------|--------|
| background  | 0.9234| 0.9456 | ✅ 背景识别很好
| cat         | 0.6234| 0.6712 | ⚠️ 猫识别一般
| dog         | 0.6234| 0.5987 | ❌ 狗识别较差
```

**分析**：
- 背景IoU高（0.92）：模型能准确区分前景和背景
- 猫IoU中等（0.62）：存在误分类，需优化
- 狗IoU较低（0.62），Recall更低（0.60）：模型对狗的召回不足，可能原因：
  1. 狗的训练样本较少
  2. 狗的姿态变化大，标注不足
  3. 狗与猫外观相似，混淆

**优化方向**：
1. 增加狗的训练样本
2. 使用数据增强（翻转、旋转）
3. 调整类别权重（增大狗的loss权重）
4. 检查标注质量

## 四、超参数调优实战

### 4.1 学习率调优

**实验设计**：

```python
# 实验1：基准配置
Init_lr = 1e-4
optimizer_type = "adam"
lr_decay_type = "cos"

# 实验2：更大学习率
Init_lr = 5e-4  # 5倍

# 实验3：更小学习率
Init_lr = 5e-5  # 0.5倍

# 实验4：SGD优化器
optimizer_type = "sgd"
Init_lr = 1e-2
weight_decay = 1e-4
```

**对比指标**：
- 训练速度（损失下降曲线）
- 最终mIoU
- 训练稳定性（loss是否震荡）

**选择标准**：
- ✅ 验证损失最低的配置
- ✅ 训练曲线平滑（无剧烈震荡）
- ✅ mIoU最高

### 4.2 输入尺寸调优

**实验对比**：

| input_shape | mIoU | 训练时间/epoch | 显存占用 | 推理速度 |
|-------------|------|----------------|----------|----------|
| [256, 256] | 0.7234 | 1.5分钟 | 2GB | 60 FPS |
| [416, 416] | 0.7856 | 3.2分钟 | 4GB | 30 FPS |
| [512, 512] | 0.8123 | 5.0分钟 | 6GB | 20 FPS |
| [640, 640] | 0.8234 | 8.5分钟 | 10GB | 12 FPS |

**结论**：
- 精度优先：选择[512, 512]或更大
- 速度优先：选择[256, 256]或[416, 416]
- 平衡选择：[416, 416]（速度和精度折中）

### 4.3 backbone网络对比

**实验配置**：

```python
# 实验1：VGG主干
backbone = "vgg"
Freeze_Epoch = 50
UnFreeze_Epoch = 100

# 实验2：ResNet50主干
backbone = "resnet50"
Freeze_Epoch = 50
UnFreeze_Epoch = 120  # ResNet需要更多epoch
```

**对比结果**：

| backbone | mIoU | 训练时间 | 模型大小 | 推理速度 |
|----------|------|----------|----------|----------|
| vgg | 0.7856 | 2小时 | 99MB | 快 |
| resnet50 | 0.8234 | 3.5小时 | 185MB | 中等 |

**选择建议**：
- 快速实验：vgg
- 精度要求高：resnet50
- 移动端部署：vgg

### 4.4 batch_size影响

**实验对比**：

```python
# 小batch（显存不足时）
Freeze_batch_size = 2
Unfreeze_batch_size = 1

# 中batch（推荐）
Freeze_batch_size = 8
Unfreeze_batch_size = 4

# 大batch（显存充足时）
Freeze_batch_size = 16
Unfreeze_batch_size = 8
```

**影响**：
- batch size ↑ → 训练稳定性 ↑，泛化能力 ↑
- batch size ↓ → 训练速度 ↓，可能陷入局部最优

**注意**：
- batch size改变时，学习率也需调整
- 经验公式：`new_lr = old_lr × √(new_batch / old_batch)`

## 五、训练问题诊断

### 5.1 过拟合诊断

**症状**：
```
Epoch 50 - train_loss: 0.123 || val_loss: 0.456
训练损失很低，验证损失很高
```

**可视化诊断**：
```python
# 在TensorBoard中观察
# loss曲线：持续下降
# val_loss曲线：先降后升或不变
```

**解决方案**：

1. **增加数据增强**：
```python
# 在utils/dataloader.py中调整
jitter = 0.5  # 从0.3增大到0.5
hue = 0.2     # 从0.1增大到0.2
```

2. **提前停止**：
```python
# 使用回调函数（train.py中已内置EvalCallback）
# 当val_loss连续N个epoch不下降时停止
```

3. **增加训练数据**：
- 收集更多样本
- 使用数据增强生成更多样本

4. **降低模型复杂度**：
```python
# 减小输入尺寸
input_shape = [256, 256]  # 从512减小到256
```

### 5.2 欠拟合诊断

**症状**：
```
Epoch 100 - train_loss: 0.567 || val_loss: 0.589
训练损失和验证损失都很高，且不再下降
```

**解决方案**：

1. **增加训练epoch**：
```python
UnFreeze_Epoch = 200  # 从100增加到200
```

2. **提高学习率**：
```python
Init_lr = 5e-4  # 从1e-4增大到5e-4
```

3. **使用更复杂的模型**：
```python
backbone = "resnet50"  # 从vgg改为resnet50
```

4. **检查数据质量**：
- 标注是否正确
- 数据是否过于复杂

### 5.3 训练不稳定诊断

**症状**：
```
Epoch 10 - train_loss: 0.523
Epoch 20 - train_loss: 0.312
Epoch 30 - train_loss: 0.689  ← 突然上升
Epoch 40 - train_loss: 0.234
```

**原因与解决**：

1. **学习率过大**：
```python
Init_lr = 1e-5  # 减小学习率
```

2. **batch size过小**：
```python
Freeze_batch_size = 8  # 增大batch size
```

3. **使用余弦退火**：
```python
lr_decay_type = "cos"  # 从step改为cos
```

### 5.4 类别不平衡问题

**症状**：
```
| background | IoU: 0.95 | ✅
| class1     | IoU: 0.12 | ❌ 极低
```

**解决方案**：

1. **调整类别权重**：
```python
# 在train.py中
cls_weights = np.array([1, 5], np.float32)  # class1权重×5
```

2. **启用Focal Loss**：
```python
focal_loss = True
```

3. **启用Dice Loss**：
```python
dice_loss = True
```

4. **采样策略**：
- 增加少数类样本
- 重复采样少数类
- 裁剪包含少数类的区域

## 六、模型选择策略

### 6.1 多个模型对比

**实验记录表**：

| 实验ID | backbone | lr | batch | epochs | mIoU | 备注 |
|-------|----------|-----|-------|--------|------|------|
| exp1 | vgg | 1e-4 | 4/2 | 100 | 0.7856 | 基准 |
| exp2 | vgg | 5e-4 | 4/2 | 100 | 0.7234 | lr太大 |

**选择标准**：
1. 优先选择mIoU最高的
2. 相同mIoU时，选择训练时间短的
3. 相同mIoU时，选择模型小的（便于部署）

### 6.2 模型集成（可选）

**简单投票法**：
```python
# 使用3个模型预测，像素级投票
model1_pred = model1.predict(image)
model2_pred = model2.predict(image)
model3_pred = model3.predict(image)

# 多数投票
final_pred = mode([model1_pred, model2_pred, model3_pred], axis=0)
```

**加权平均法**：
```python
# 根据验证集性能加权
weight1, weight2, weight3 = 0.5, 0.3, 0.2
final_pred = weight1*model1_pred + weight2*model2_pred + weight3*model3_pred
```
